## 自动检查

- JVM：更新版本号数值比较、正式资产来源限制、草稿/预发布拒绝与摘要读取。
- Android：拒绝同版本和错误包名的更新 APK，验证更新 FileProvider 不暴露音乐目录。
- JVM：分享文案链接提取、域名边界、API JSON、路由 JSON、URL 编码的 RENDER_DATA、不可访问与畸形页面。
- Android：Room 收藏、重命名与外键级联；0.1.0 JSON 迁移可重入且不覆盖已有编辑。
- Android：Media3 对真实 MP4 提取音轨，输出具有音频且不含视频，并验证时长。
- Compose：音乐库、主题、歌单创建、导入入口、全屏播放和异常分享反馈，保存页面截图。

执行结果以对应提交的 GitHub Actions 日志和测试报告为准。远程站点返回可访问资源的能力不能由本地解析样例测试代替。

## 手动验收

1. 覆盖安装后确认 0.1.0 歌曲仍在；收藏、建歌单、改名、换封面、重启验证数据。
2. 分别导入 MP3/M4A/FLAC/WAV/OGG；尝试损坏文件、空文件与空间不足。
3. 选择带音轨的视频，确认输出可播放；尝试无音轨视频；提取中取消并重新导入。
4. 播放时锁屏、切后台、蓝牙按钮切歌，断开耳机、接电话或由其他应用抢占音频焦点。
5. 调整进度、随机和循环，确认队列与当前播放一致；删除当前歌曲时停止访问其副本。
6. 导出文件到系统文件提供方，用其他播放器打开；确认删除应用副本不影响原始来源文件。
7. 自定义图片、字体、主题色、透明度与模糊，重启验证。开启低性能模式检查动画与模糊关闭。
8. 从抖音系统分享和粘贴入口测试短链/长链、不可访问链接与断网。解析成功后只在确认保存时下载；失败可进入本地视频。

0.1.0 的本地导入与播放已由项目发起人在手机上验证。本版本新增功能的跨厂商蓝牙、省电策略及真实抖音链接仍需相应设备与可用资源验证，不能仅凭构建通过推定全部真机兼容。

## 2026-11-05 真实分享检查

发起人提供的抖音短链可跳转到视频 `7703207505506385481`。旧版分享页返回 HTTP 200 但路由数据不含媒体，旧详情接口触发站点访问校验。研究 `wujunwei928/parse-video-py` 的近期实现后，新增公开 `slidesinfo` 接口，已返回此视频的标题、时长与视频地址。已下载约 72.7 MB 视频，确认含 H.264 + AAC，并在开发环境提取出仅含 AAC 的 M4A；时长约 358.96 秒。还通过临时 JVM 测试直接调用本项目 Kotlin 解析器与下载器，确认下载 72747738 字节。Android 端提取另由自生成 MP4 的 Media3 设备测试验证。

完整分享参数、Cookie 与下载内容不提交到仓库。解析器单元测试使用自造 JSON，不打包实际视频内容。


## 1.0.4 进度条交互回归

- 拖动到约 75% 时，滑块与时间预览跟随手指；松手前不提交 seek，松手只提交一次。
- 模拟播放器仍返回旧进度时，滑块保持目标位置；播放器确认后恢复实际进度。
- 未确认跳转时切歌，清除上一首的目标位置。
- 手动推进 Compose 测试时钟，确认正常播放能在连续帧读取新位置，无需父页面更新。
- 正常帧循环使用 Compose 的无限动画策略，避免自动测试时钟持续等待进度刷新；暂停及低性能模式降低轮询频率。

手机验收：播放一首较长歌曲，连续往返拖动并反复松手；分别测试播放中、暂停时、接近结尾、切歌后和低性能模式。检查手指跟随、松手回跳及实际音频跳转。设备回归不等同于对所有手机的帧耗时测量。
